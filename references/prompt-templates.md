# 提示词模板 · 职规赛/创赛 PPT

## 一、通用可编辑性铁律（每次生成 PPT 必写）

```
生成要求：
1. 每一页的标题、正文、配图、图标、数据、页码均为独立对象，禁止把整页压成一张图片；
2. 文字必须是可编辑文本对象，不得作为像素渲染进背景图；
3. 数据图表使用可编辑数据表驱动，不得转成图片；
4. 背景为透明或纯色，不携带任何无关底色；
5. 元素位置、大小、比例严格遵循版式规格表；
6. 输出 .pptx，而非图片序列。

请检查最终预览是否可继续编辑，避免出现元素偏移、尺寸变化、顺序错误、元素误删或文字变成图片。
```

## 二、版式规格表（写进提示词，作为硬约束）

| 项 | 值 |
|---|---|
| 画布 | 16:9（33.87cm × 19.05cm / 1280×720 pt） |
| 四边留白 | 左右各 ≥ 60pt，上 ≥ 48pt，下 ≥ 48pt |
| 内容安全区 | 距画布边缘 ≥ 5%，元素不得越界 |
| 标题对齐 | 统一左对齐（或按方向锁定），x 坐标固定 |
| 正文起始 y | 标题下方 ≥ 32pt |
| 字号层级 | 标题 32-40pt / 小标题 24-28pt / 正文 16-20pt / 注释 ≥ 12pt |
| 主色 | 每套方向仅一个主色 + 一个强调色，全局沿用 |

## 三、版式方向定义（一次给 3 个，差异在骨架不在颜色）

| 方向 | 主色倾向 | 骨架特征 | 图示风格 |
|---|---|---|---|
| 沉稳答辩风 | 深蓝 / 藏青 | 左文右图，标题压顶 | 简洁线性图标 |
| 科技感深色 | 深青 / 炭黑 | 通栏大数字 + 分块 | 细线 + 发光点 |
| 极简留白 | 白 / 浅灰 | 大量留白，单栏 | 无图标，纯字号层级 |

⚠️ 差异必须在**结构、密度、图示**上，不能只是换主色。

## 六、职规赛骨架参考

- **封面**：标题 + 姓名 + 赛道（对应组别与赛道）
- **目录**
- **职业目标（按当届官方评分标准）：方向定位 + 行业契合 + 外部验证
- **学习实践行动（权重以当届官方评分标准为准）：按阶段列成果，每项挂可核验证据

- **结尾**：致谢 + 联系方式

## 八、NotebookLM 式提示词工程（出图/ 出大纲通用）

参考 NotebookLM 的做法：它不是靠「提示词写得更华丽」，而是靠**结构化收敛 + 上下文预算管理 + 迭代式约束**。拆成四条可直接套用的规矩。

### 8.1 四层收敛结构（出图提示词模板）

所有出图提示词按这四层写，**顺序不能乱**。实测这样写出来的图稳定很多，而且元素分布可预测、能被算法切：

```
Subject:  <画什么，一句话，只说主体不要修饰>
Scene:    <什么环境/背景/氛围，只说场景>
Composition: <构图与留白—— 决定能不能切图的关键词>
Style:    <风格与配色，扁平优先>
Hard constraints: <硬约束，必须以Absolutely no 开头成串列>
```

**为什么这样有效**：
- `Composition` 层是**给算法看的**，不是给模型看的。写「generous gap」「isolated with clear background」「plain white background」，`debg` + `detect` 就能切开；不写就是连成一坨，只能当背景图。
- `Hard constraints` 层固定用 `Absolutely no text, no letters, no numbers, no watermark` 起头。图像模型最爱偷偷塞文字，塞了就白跑。

### 8.2 上下文预算：先减，再加

NotebookLM 处理长资料的核心是**不把全部内容塞进 prompt**。同理：

| 做法 | ❌ 不好 | ✅ 好 |
|---|---|---|
| 出图 | 把整个 PPT 主题、页数、风格全写进一条 prompt | 一条prompt 只画一个主体，批次靠 `jobs.json` 分 |
| 出大纲 | 一次要「结构+文风+字数+禁用词+格式」 | 先只出**大纲**（page + points），文风等落位时再定 |
| 文案 | 一次生成全部页 | 按页生成，出错只重生成那一页 |

**判断标准**：一条 prompt 里出现第二个 `and also`，就该拆了。

### 8.3 可切性约束（这是 asset-slicer 联动的前提）

要在 PPT 里当「可替换素材」用的图，提示词必须加：

```
Composition: each element sits inside its own generous gap,
              plain white background, evenly spaced
```

加了这段，`debg` 能去底、`detect` 能切元素、`cards` 能统一规格。
不加，图就只能整张当底图——**那就是装饰，不是资产**。

### 8.4 迭代式约束（先看再改，不要一次写死）

不要指望一条提示词出成品。流程是：

```
第 1 轮：出图 → 看结果 → 找出问题（塞字了 / 元素粘连 / 留白不够）
第 2 轮：只改问题对应的那一层，通常是 Composition 或 Hard constraints
第 3 轮：仍不理想 → 换模型（gpt-image-2 ↔ gpt-image-2.5-flare ↔ gemini-3-pro-image）
```

**不要做的事**：第 1 轮不满意就重写整条 prompt。前三轮的成本会指数上升，而改动往往只在一层里。

### 8.5 批量出图用 jobs.json

```json
[
  {"name": "cover", "model": "gpt-image-2", "size": "1K", "prompt": "Subject: ..."},
  {"name": "architecture", "model": "gpt-image-2", "size": "1K", "prompt": "Subject: ..."}
]
```

```bash
python asset-slicer/scripts/slice.py artgen --jobsjson jobs.json --outdir ./raw
```

每个 `name` 独立命名、独立失败不拖累其他。**出图阶段统一 1K 试构图，定稿后只对选中的那张重跑 2K/4K**——省积分。

### 8.6 出图后必跑的检查

| 检查 | 命令 | 不通过怎么办 |
|---|---|---|
| 有没有偷偷塞文字 | 肉眼看 | 加 `Hard constraints` 重跑 |
| 深色底图 | 提示词含 `dark background` | **必须先 `debg`**，否则 `detect` 只认到1 个元素 |
| 元素粘连 | `detect` 元素数 < 预期 | 改 `Composition` 加间隙 |
| 需不需要整张用 | 看有没有元素粘连 | 粘连严重就别切了，当底图用 |
